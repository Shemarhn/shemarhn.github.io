# Commercial search market and acquisition priorities — 2 November 2026

This is the research companion to the implementation report. Research was performed on 2 November in Jamaica time using built-in search and the Codex in-app browser, never the owner's personal browser. Read alongside [the previous baseline](ORGANIC-GROWTH-2026-10-27.md). **Observed** means a source or page was inspected; **inferred** means a commercial judgment from those observations; **recommended** means a proposed action. No keyword volumes, backlink metrics, neutral ranking positions, or inquiry forecasts are invented.

## What the current market supports

**Observed:** Commercial provider pages exist for all the main infrastructure clusters. Google in-app search for `Proxmox migration consultant` returned specialist migration pages, the official Proxmox directory, Cirrus Data, servinga, Blueternal Solutions, Ekkum and Crafty Penguins, plus a video block. The related-search area included partner/subscription/login phrases as well as consulting; those suggestions are not automatically buyer demand. Bing in-app search for `Linux server consultant` returned Shattered Silicon, Revenni, LOD, Linux Consulting Services, Progent, Alessio Ligabue, Crafty Penguins, a marketplace and a comparison roundup. A visible result count is not a demand or difficulty metric.

**Inferred:** A clear service page is appropriate for hire-now terms. An independent consultant can credibly compete on tightly defined assessment, implementation and handover work; this does not establish that these queries are easy to rank for. Broad `AWS consultant`, `DevOps consultant` and `Linux consultant` terms also encounter established providers, marketplaces and employment intent. Technical problem specificity is a stronger near-term acquisition hypothesis than pursuing generic head terms alone.

**Recommended:** Keep one substantial destination per service. Improve the existing ten-page service system and evidence connections before adding new commercial URLs. The Proxmox page was introduced only six days before this review; allow measurement and recrawl time. Do not create AWS/Azure/Terraform/migration synonyms as thin standalone pages.

## Opportunity scoring without fake precision

**Recommended method:** score each opportunity 1–5 for buyer intent (I), business fit (F), evidence (E), page gap/improvement value (G), contestability (C) and effort efficiency (T). Weighted qualitative score = `4I + 3F + 3E + 2G + C + T` (maximum 70). These are editorial judgments, not measured SEO-difficulty scores. Evidence 5 means directly relevant executed examples, not paid-client proof. Contestability remains conservative where link strength is unknown. Effort efficiency 5 means a small supported change.

Keep measured impressions/ranking as a separate **unknown** field until available; never turn missing data into zero demand. Once query data exists, prioritize verified commercial impressions in positions 4–20, then 21–50, with the appropriate landing page and a real improvement to make. Use clicks, inquiry relevance and qualification to reassess business value.

**Recommended quick wins:** relevant evidence links, readable service scope, stronger path from article/work to service/contact, and sound measurement. **Medium term:** decision content, genuine professional references and narrowly scoped distribution. **Long term:** earned mentions, eligible directory inclusion, professional case studies with permission and broader cloud authority. None is a forecast that ranking will improve in 30 days.

## Content decisions

**Recommended first content:** (1) a Proxmox migration-readiness checklist grounded in inventory, guest/storage/network compatibility, pilot, backups, acceptance and rollback; (2) restore-test guidance grounded in the NORTHSTAR record, distinguishing data checks, application checks and observed timings from promises. These are editorial candidates supported by commercial problem relevance and current terminology, not proven keyword volumes. Improve an existing article when it already answers the same question.

Next candidates, only after reviewing actual query/inquiry evidence: monthly Linux maintenance scope; infrastructure handover/runbook acceptance; Terraform state ownership. Each should show a concrete example, cite current official technical documentation, state limits, link to one primary service and use a restrained contact path. Do not create calculators, interactive lead magnets, comparison pages, city pages or schedule-driven filler. Dates must change only with substantive updates.

## What changes the priorities next

**Recommended:** revisit on 9 November 2026, then weekly. Use actual Search Console 7/28-day data and three-month context, keep the query/page/device/country dimensions, identify commercial impressions with no clicks and inspect positions 4–10/11–20/21–50. Country and device guide usability and buyer fit; they do not justify fabricated local pages. Compare like periods, record collection dates and allow for reporting lag.

If one service gains relevant impressions, inspect its intent alignment and conversion path before creating another page. If two pages repeatedly split the same buyer query, compare purpose and outcomes; strengthen one primary destination, merge only truly duplicative material and redirect only after checking existing links. If traffic rises without useful inquiries, review buyer fit, evidence, scoping and form friction. If a service produces qualified work, invest in a permissioned professional case study and relevant authority. Search impressions, indexing, visits, inquiries and clients remain separate outcomes.
