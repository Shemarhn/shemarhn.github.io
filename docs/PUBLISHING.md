# Weekly publishing

## Choice: Git-based Astro content collections

Markdown gives a $0 initial publishing workflow, static crawlable articles, version history, schema validation, and a small security surface. A GitHub browser edit is sufficient for weekly publication; no public CMS login or database publishing service is needed. A Git-based CMS can be added later if the editing experience becomes the constraint. A custom CMS was not added simply to store articles.

## Add an article

Create `src/content/insights/your-article-slug.md` in GitHub’s editor or locally. The filename becomes `/insights/your-article-slug/`.

```yaml
---
title: 'A specific question, answered usefully'
date: 2026-11-02
author: Shemar Marks
category: Cloud Infrastructure
tags: [AWS, operations]
excerpt: 'One useful sentence describing the actual takeaway.'
readTime: 5
hero: /assets/social-preview.png
status: draft
relatedServices: [cloud-infrastructure]
relatedCases: [northstar]
social:
  enabled: true
  linkedin: 'Optional LinkedIn-native version of the idea.'
  x: 'Optional concise X-native hook.'
---
```

Write the body in Markdown. Use H2 headings (`##`) for sections; the page template supplies the H1 and generates the table of contents. Use descriptive links to the relevant commercial service and evidence-backed case study. Place images in `public/assets/`, optimize them, include alt text, and supply dimensions where authoring HTML.

Supported fields include title, filename slug, publication/updated dates, author, category, tags, excerpt, reading time, hero/social image, Markdown body, related services/cases, draft status, optional canonical URL, and optional per-platform social copy. Related articles, CTA, metadata, BlogPosting schema, author link, TOC, and share links are generated by the template.

## Review and publish

1. Verify the technical claims against current primary documentation and your actual evidence.
2. Distinguish executed work from examples. Do not fabricate client outcomes.
3. Add a meaningful excerpt and specific title. Review links, diagrams, and any code carefully.
4. Add platform-specific LinkedIn/X copy when useful. Omitting it uses a restrained title/excerpt fallback.
5. Set `status: published` when ready; leave future dates for scheduled publication.
6. Open a pull request, inspect the build, and merge after review. Deployment uses the protected production environment.

Only entries marked published with a date at or before build time produce pages or appear in lists, RSS, sitemap, or the internal social feed. Future posts become visible on the first successful scheduled build after their date. The daily GitHub workflow is best-effort, not a precise publishing scheduler; GitHub may delay scheduled jobs. YAML dates without times mean midnight UTC. Use a full ISO timestamp with `-05:00` for an intentional Jamaica time.

The three initial articles are launch copy based on the preserved lab evidence and primary technical sources. Owner/editorial review is still required before deployment. No ongoing weekly articles have been invented or auto-published beyond this initial set.

## LinkedIn and X syndication

The website remains the canonical article. The Worker synchronizes each published Insight into a separate LinkedIn and X draft with UTM-tagged links. Launch uses `SOCIAL_MODE=review`, so publishing an article does **not** automatically post to social accounts. Visit `/admin/social/` after Cloudflare Access sign-in to edit, approve, publish, or skip each platform draft.

Once the provider integrations and voice have been proven in production, `SOCIAL_MODE=automatic` can be considered deliberately. Do not enable it merely because credentials exist. See [SOCIAL.md](SOCIAL.md) for provider setup, duplicate protection, and failure behavior.

## Changing prices

The `pricing` array in `src/data/site.ts` controls engagement cards. All currently say “Quoted to your scope.” Add approved currency, starting-price/range text, assumptions, and applicable minimum scope to that data and the pricing template when you decide the numbers. The old documentation-review fee was not repurposed as a public price.

## References

Public submissions go to `/references/submit/`. After authenticated Access sign-in, `/admin/` lists pending and other submissions. Verify the relationship and permission; edit quotes only with the client’s agreement; select status and optional case study; approve value display separately. Approved rows appear at request time, without a site rebuild. A needs-changes or rejected reference is immediately removed from the public projection. `/admin/data/` provides authenticated deletion of the website-held copy when removal is required.
