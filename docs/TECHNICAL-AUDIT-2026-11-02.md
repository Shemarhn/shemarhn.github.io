## Forms, authentication and operational boundaries

- **Observed:** inquiries are accepted only after same-origin validation, bounded JSON parsing, service/field checks, honeypot, rate limiting and server-verified Turnstile. A D1 batch stores the inquiry and separate CRM/email outbox jobs before acknowledgment. Client UUID replay protection avoids duplicated durable inquiries.
- **Observed:** acknowledgment delivery and CRM synchronization have independent durable retries and leases. Successful browser submission is distinct from email delivery, CRM acceptance, qualification and a won engagement.
- **Observed:** administration requires Cloudflare Access JWT verification plus the server-side email allowlist; local form testing is loopback-only and does not bypass administrator authentication. Public references are pending until authorized moderation; identity and commercial-value permissions remain separate. Public projection excludes private email and moderation fields.
- **Observed:** no schema migration, Worker routing, authentication, Turnstile, delivery, reference permissions, CRM credentials, DNS, production writes or social publishing behavior changed in this pass.
- **Observed/corrected documentation:** `worker/entry.ts` already runs 365-day retention for website-held inquiries whose CRM job is delivered, and pending/rejected/needs-changes references. Previous architecture/privacy wording did not accurately describe that handler. Documentation now matches the existing implementation; retention code is unchanged. CRM/email copies are separate.

## What existing measurement can establish

## Implemented corrections

1. **Observed gap, fixed:** new inquiry attribution distinguishes `google`, `bing`, `direct`, `referral`, `paid`, `campaign` and `unknown`. Explicit paid-click/paid-medium signals take precedence. No click IDs are retained. Existing Google/Bing subset event names are unchanged; there are no new trackers, cookies, identifiers or event dimensions.
2. **Observed gap, fixed:** first-touch landing page, referrer, channel and UTM context now remain consistent throughout the tab. Later internal URL parameters cannot overwrite only the campaign while keeping an older landing/source. Malformed stored values recover safely; empty legacy channels become unknown rather than being reclassified as direct.
3. **Observed gap, fixed:** DNT, GPC and the existing device opt-out now suppress optional first-touch retention as well as first-party events. Disabled context is cleared from session storage. The essential current form page/CTA/submission details remain available for responding to a deliberately submitted inquiry. Privacy wording explains this boundary.
4. **Recommended workflow, implemented artifact:** [read-only weekly SQL](../scripts/weekly-acquisition.sql) returns this/prior 7-day and 28-day page/event counts, actual inquiries by coarse channel/landing/service, reference statuses and delivery health. It uses complete UTC days and `julianday()` for ISO timestamps, avoiding mixed `T`/space timestamp comparisons and partial-day windows. It selects no names, emails, inquiry descriptions or raw referrers.

These corrections affect data collected after deployment. They cannot reconstruct historical channel data or justify a before/after conversion uplift claim.

## Weekly use and KPI interpretation

**Recommended:** once a week, export the SELECT results from Cloudflare D1 and align them with Search Console/Bing reporting dates. The SQL excludes the current incomplete UTC day; note the provider's timezone and reporting lag rather than assuming day-for-day alignment. A Jamaica calendar day is not a UTC day. Retain dated aggregate exports outside public Git when commercial data should remain private.

Record, in priority order:

1. Qualified organic inquiries and won opportunities, using manually reviewed CRM records.
2. Saved Google/Bing-attributed inquiries and their selected service/first landing.
3. Google/Bing email, contact CTA and successful browser submission actions, separately from saved inquiries.
4. Service-page search clicks and nonbrand commercial query clicks from webmaster reports.
5. High-intent query impressions/position bands and indexed commercial pages.
6. Base page views, case-study views and other supporting interest metrics.

Use action ratios only as diagnostic rates, with the denominator and privacy limitations stated. For example, organic contact actions divided by organic page-view actions is not a unique-visitor conversion rate. Never add CTA clicks, submission events and saved inquiry records into a single lead total. Historical blank channels stay unknown.

**Recommended:** judge low-volume acquisition over multiple weeks. Do not rewrite titles from a handful of impressions; investigate wrong-page ranking, a meaningful query trend, inaccurate copy, broken contact paths or an actual change in service scope. Qualification needs one consistent operator decision and an inquiry ID in the private CRM; aggregate reporting alone cannot supply it.
