Synthetic engagement · Executed infrastructure lab

Northstar Repairs

From one Proxmox VM to an AWS deployment with a tested rebuild and restore workflow.

TerraformEC2 + S3CloudWatch + SNSPython + SQLite
12min

Observed recovery
in one lab exercise

The problem

A synthetic repair shop's job register depended on a single VM. The application and its SQLite data needed a recovery path beyond that server.

The work

Migrate the workload to AWS, define infrastructure in Terraform, separate backups into versioned S3 storage and test replacement-server recovery.

The result

Six jobs recovered, including DR-TEST. SQLite integrity and application health returned ok. One recovery took 12 minutes, including a CloudShell interruption.

Inspect Northstar evidence

See the evidence

The lab is complete. AWS resources were destroyed after evidence preservation; cleanup checks found no active Northstar resources. This synthetic scenario is a portfolio exercise. The 12-minute result is a single observation, not a production SLA; no measured RPO is claimed.

Synthetic engagement · Executed local Ubuntu / WSL2 lab

Cedarfield

Linux application-server hardening and an operable maintenance handover.

Linux + systemdSSH + UFWFail2banOperations
Reduced exposureTwo open tested ports reduced to one
from an isolated owned peer
The problem

A working Linux app had root execution, broadly readable configuration, permissive SSH settings and an unnecessary service.

The work

Capture the baseline, apply risk-driven access, network and service controls, verify the workload, and exercise rollback.

The result

Dedicated service identity, private 0600 config, verified key-only SSH and firewall denial. A safe failed-login test triggered a real Fail2ban ban. The three-record app stayed healthy.

Local Ubuntu/WSL2 execution with isolated server/client namespaces. Backup integrity, rollback and final host checks passed. Same-disk backup and local health logs remain limitations; no Proxmox or production claim.
